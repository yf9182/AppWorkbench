# 验收与证据

## 框架验收

框架完成与产品版本完成分别报告。单元测试验证门禁、状态和传输；真实只读调查验证账号/资源访问；生产部署、TestFlight、真机和购买须另有实际证据。当前实现即使通过自动测试，也不能声称两个试点迭代已验收。

必要场景：

- 单 App、纯网站、多仓库及共享服务登记成功；身份、目标或凭据不匹配拒绝依赖动作。
- 未确认计划、修订后旧确认、旧候选评审/检查、变更配置、非独立评审均不能放行发布。
- 低样本与部分数据缺失呈现未知，其他独立工作可继续；未获收入不写为零。
- 暂停阻止新动作，恢复不丢状态；中断或超时先远端核对，不重复上传或部署。
- 多仓库部分交付可独立恢复，后端发布要求旧客户端兼容证据，依赖未满足不越级。
- 真人证据不能由自动测试代签；日志、提示、导出和面板不含秘密原值。
- 凭据替换不改产品源码；迁移后的签名/session 本机验证标记重新核对。

## 产品候选验收

每项证据至少关联来源、观察时间、目标及候选提交；证据文件存储摘要。命令失败、无证据或目标无法核对为 failed/unverified，不能改成 ready。相关检查通过后再做独立候选评审；修改后重验受影响环节，避免重复全量。

网站/后端交付记录 PR、合并提交、部署标识、线上 URL 和冒烟结果，失败说明实际回退状态。调用生产写入前核验计划范围、目标配置、提交、锁和去重。

iOS 分四层：真实归档与分发签名；TestFlight 上传/处理远端状态；用户真机核心路径及购买/恢复/既有权益；正式资料和手动发布设置回读。缺少后两层时可以是“TF 可测试”，不能是“正式准备完成”。商店提审和正式发布仍由用户操作。

## 两个真实试点

CalorieSnapshot：复用已存在的采集、指标、签名和发布入口及账本，核对旧运行归属，提供新的调查与一个有价值的计划。AI Pet Studio：关联三个仓库，核实 Analytics SDK 缺口、后端兼容、Web 测试/发布和 iOS 分发身份，提供独立计划。两份计划均待用户分别确认后才实施真实版本，不能以建设框架的指令代替。

完成标准是各试点实际经过调查、明确确认、真实候选、独立评审、必要测试、适用目标交付及真人反馈。用户待办、费用测试待办、外部权限缺口必须单独列出；不为证明框架制造无价值空版本。
