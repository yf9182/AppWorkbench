# 对话工作流

## 入口与登记

从代码目录执行 `bin/wb --help` 获取实际参数。Skill 以 `APP_WORKBENCH_CODE` 或 `~/AppWorkbench` 定位代码；CLI 以 `APP_WORKBENCH_HOME` 或 `~/.config/app-workbench` 定位私人状态。所有命令输出 `{ok,command,result}`，失败输出 `{ok:false,error:{code,message}}` 并非零退出；不从退出码推导未返回的远端成功。

| 阶段 | CLI 入口 | 产出 |
| --- | --- | --- |
| 初始化/登记 | `init`、`product list/show/register/inspect` | 产品目标、仓库、身份、能力缺口 |
| 调查 | `collect PRODUCT`、`evidence add` | 独立数据源状态与可追溯证据 |
| 计划 | `iteration create PRODUCT --plan FILE` | 保存计划及摘要 |
| 确认/变更 | `iteration approve`、`iteration revise` | 真实用户确认绑定当前修订 |
| 候选 | `candidate set ID --file JSON` | 实际仓库提交和制品身份 |
| 验证 | `review record`、`check` | 独立评审、相关检查及摘要 |
| 交付 | `deliver`、`reconcile` | 持久化意图、远端结果与恢复 |
| 反馈 | `accept ID --file JSON` | 对应构建的真人反馈 |
| 进度/恢复 | `iteration status/pause/resume` | 持久状态、依赖、剩余步骤 |
| 面板/迁移 | `export`、`serve`、`backup/restore` | 脱敏只读投影、私人备份 |

不要把表中动作理解为每轮全部执行。按当前阶段与能力选择最少必要命令；注册和改动产品配置后先重新 inspect。使用检查参数和 JSON 字段前查看子命令帮助及实现接口。

## 从调查到确认

先识别产品及共享依赖，核对真实代码和线上目标；初期默认最近 28 天，但记录实际可读范围。使用分析模板区分已验证、描述性结论、假设与测量缺口。每项来源记录 API/仓库/URL、采集时间、日期、币种、版本和事件定义。无收入权限记录未知；不同币种不得直接相加。市场调查附查询时间和链接。

推荐一个计划，包含问题、依据、范围、排除项、验收、后端兼容、发布顺序、效果观察和预算。保存后呈现其修订标识。用户“按这份计划执行”仅可确认上下文唯一对应的修订，原话与人类身份写入 approve。不能用脚本或 Agent 身份生成批准。新修订重新确认；一般实现选择无需重复问。

## 候选到交付

工作开始前检查原有执行者，必要时明确交接；不重置旧账本或自动化。协调者分配单人文件所有权，最多两名子 Agent，不强制满并发。最终候选必须是实际提交，检查与评审记录绑定提交和目标。独立评审者未参与实现，先看原始候选，不接收希望其通过的结论。

目标发布按依赖推进：后端兼容线上旧客户端，再 Web/iOS。配置或候选变化时，依赖它的测试/评审失效。未知或失败能力仅阻止依赖目标。网站和后端只在门禁通过后 PR、合并、部署、冒烟；回退必须有目标配置及证据。App 的归档、上传与正式准备分离；上传后核对实际远端处理，真人业务验收后才正式准备，最终待用户提审。

每个外部动作持久化目标、意图、候选、结果。超时/中断标为 uncertain；先通过已认证 API 查询真实远端，reconcile 后再决定重试。不能拿本地陈述“应该成功”解除去重控制，也不能用 mock 回应为生产证据。暂停阻止新执行，恢复保留已完成步骤。

## 反馈与迁移

反馈绑定用户实际测试的版本与构建。范围内缺陷继续修，新增特性形成下一份计划；相关候选改变使受影响验收失效。上线效果从真实发布时间取数，按版本和口径隔离，不从 TestFlight 上传推导生产增长。

备份运行库与报告使用 CLI，凭据使用既有加密迁移工具。转移解密密钥独立于密文包，恢复目标不能覆盖现存目录。新机器核验平台会话、文件权限、签名、目标和源代码；未重验的能力仍 unverified。查看面板只用脱敏导出，不返回凭据路径内容或原始 provider 响应。

## 恢复边界

外部动作、远端核对证据和配置均绑定当前计划。旧计划或旧目标的成功记录不能放行新计划；命令拒绝重复发布，应先核对旧迭代结果，明确是否需要新候选。

本地归档中断不推导成功；恢复记录该次未完成，允许在新目录重建。上传必须引用此计划、此提交实际归档导出的 IPA；补入 IPA 引用保留同一代码候选的检查与独立评审，实际签名和制品身份仍在上传前校验。

`prepare_store` 的 `metadata_sha256` 必须与真人元数据验收记录一致。通用适配器验证已存在的远端截图摘要、顺序和处理完成状态。新增截图可用 CalorieSnapshot 既有上传流程；其他产品目前须先把已验收截图放入商店草稿，不能把本地截图存在当作远端完成。

分别恢复凭据包与状态包后，可用 `restore --credential-home` 将独立凭据恢复目录中的维护工具与凭据合并至最终新目录，保留状态包的产品清单。钥匙串安装和平台身份仍需重验。
